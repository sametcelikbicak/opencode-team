# Decision: copy vs link for npm install

Date: 2026-11-02  
Status: accepted  
Related issue: #47, #52

## Decision

npm install uses **symlink/link by default** (same as `install.sh` behavior), with `--copy` flag for copy mode.

- Default (`symlink`): symlinks `agents/`, `commands/`, `team.yaml`, `team/AGENTS.md`, `skills/team-*` into the OpenCode config dir. Edits in the repo take effect immediately.
- `--copy`: copies files instead of symlinking. Safer for npm global installs where the package directory may be read-only or cleaned by npm.
- `--dev`: explicit alias for link mode (developer workflow).

## Alternatives considered

| Option | Reason rejected |
|--------|-----------------|
| Copy default | Breaks the "edit in repo, takes effect immediately" workflow that symlink users expect |
| Symlink default | **Selected** — matches existing `install.sh` behavior; users already familiar with it |
| Copy only | Would require `--link` flag for dev mode; more complex |

## Notes

- Windows symlink creation requires Administrator or Developer Mode; `--copy` avoids this.
- Manifest at `<config>/.opencode-team-manifest.json` tracks installed files with type and hash for safe uninstall.
